## 11.1 — Which customer actions are recorded in the tenant audit log?

The tenant audit log records sign-ins, user and role changes, API token creation or revocation, exports and case deletions. Each event includes a UTC timestamp, tenant, actor, event type and source address when available. Case message bodies and attachment contents are excluded.

## 11.2 — How long can customers access audit events?

Enterprise tenants can query 365 days of audit events; Starter tenants can query 30 days. Customers needing longer retention must export events to their own archive before that window expires. Audit-event retention is separate from deleted case retention.

## 11.3 — Can tenant administrators alter or delete individual audit events?

No. Tenant administrators have read/export access only. Events are written to append-only storage through the audit service, and production operators cannot alter events through the application. Administrative access to the backing storage is separately restricted and logged.

## 11.4 — How can administrators export tenant audit events?

Enterprise administrators can export audit events as paginated JSON through the Audit Events API or download CSV in the console. The API supports timestamp filters and cursor pagination. There is no native push connector to a customer SIEM; customers operate their own collector.

## 11.5 — How are suspicious production activities detected?

Security alerts cover repeated authentication failures, unusual privileged access, bulk exports and unexpected cloud configuration changes. An on-call responder triages high-priority alerts continuously. Customers do not receive raw internal detection rules or direct access to the production SIEM.
