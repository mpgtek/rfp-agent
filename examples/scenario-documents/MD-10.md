## 10.1 — What are the remediation targets for vulnerabilities?

Confirmed critical vulnerabilities have a 72-hour remediation target and high findings have a 14-day target. Medium and low findings target 60 and 120 days respectively. These are internal operating targets; any exception needs documented risk acceptance.

## 10.2 — How frequently are infrastructure vulnerabilities scanned?

Container images are scanned at build and daily in the registry. Managed-host and cloud configuration checks run at least daily. Internet-exposed assets receive a weekly authenticated scan where supported and additional scanning after significant changes.

## 10.3 — How can researchers report a security vulnerability?

Researchers can use the published security-report form at the fictional example.invalid security portal. Reports enter the security triage queue and receive an initial response within two business days. There is no paid public bug-bounty program in this scenario.

## 10.4 — How are unsupported operating systems and runtimes handled?

Platform inventories operating-system images and runtime versions monthly. End-of-support components must be upgraded or covered by an approved short-lived exception with compensating controls. Production containers are rebuilt from maintained base images.

## 10.5 — How are newly disclosed critical vulnerabilities triaged?

Security determines exposure using the component inventory and running image versions, then opens an incident or expedited patch ticket as appropriate. Internet exposure, exploit availability and privilege impact influence priority; a scanner severity number alone does not determine closure.
