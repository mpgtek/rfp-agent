## 9.1 — What review is required before code reaches production?

Production changes require a pull request, automated test checks and review by an engineer other than the author. Branch protection blocks direct pushes to the release branch. Emergency changes are reviewed retrospectively within one business day.

## 9.2 — How is security incorporated into software design?

New authentication flows, sensitive-data handling and cross-tenant features require a threat model during design review. Security records identified trust boundaries and abuse cases, and tracks mitigation work before the feature can be enabled broadly.

## 9.3 — What automated application security testing runs in the build?

The build runs static analysis, secret detection and dependency scanning on pull requests. High-severity confirmed issues block release unless an approved, time-limited exception exists. Scanner output alone is not treated as proof that the application is vulnerability-free.

## 9.4 — How are third-party software dependencies controlled?

Dependencies are pinned through reviewed lockfiles and scanned on every build and daily against updated advisories. The build produces an internal software bill of materials. External distribution of the full SBOM requires a security review because it contains implementation detail.

## 9.5 — How are releases rolled back?

Application releases use staged rollout with health checks and a retained previous container image. Operators can roll back application code within minutes. Database migrations must remain backward-compatible during rollout; destructive migrations require a separate recovery plan.
