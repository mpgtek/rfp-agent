## 5.1 — How is customer data encrypted at rest?

Production database volumes, object storage and backups use AES-256 encryption with cloud KMS-managed keys. This protects stored media; authorized application processes can still decrypt data to serve customer requests. It is not end-to-end encryption.

## 5.2 — Which transport encryption versions are accepted?

Public web and API endpoints accept TLS 1.2 and TLS 1.3. TLS 1.0 and 1.1 are disabled. HTTP requests redirect to HTTPS, and production web responses include HSTS.

## 5.3 — Are customer-managed encryption keys supported?

No. MeridianDesk currently supports provider-managed KMS keys only. Bring-your-own-key, hold-your-own-key and customer-triggered cryptographic erasure are not available. Customers cannot upload their own KMS key to an Enterprise tenant.

## 5.4 — Where is mutual TLS used?

Mutual TLS authenticates selected internal service-to-service connections in the production cluster. Public API clients authenticate with scoped bearer tokens; client-certificate authentication at the public API edge is not supported.

## 5.5 — How are encryption keys and application secrets rotated?

KMS master keys use annual automatic rotation. Database credentials are rotated at least every 90 days and after suspected exposure. Application secrets are retrieved from a secrets manager, not stored in source code or build images.
