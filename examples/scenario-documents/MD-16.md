## 16.1 — Which public API resources are available?

The REST API supports cases, contacts, comments, attachments and audit-event reads on eligible plans. Requests and responses use JSON except binary attachment transfers. There is no GraphQL endpoint and no direct SQL access to the production database.

## 16.2 — What API rate limits apply?

The default limit is 600 requests per minute per tenant, with a burst allowance of 100 requests. A limited request returns HTTP 429 with a Retry-After header. Higher sustained limits require capacity review and are not automatically included in Enterprise.

## 16.3 — How are public API changes versioned?

Breaking changes require a new major API version with at least 12 months' published deprecation notice for the previous supported version. Additive fields can be introduced within a major version, so clients must ignore unknown response fields.

## 16.4 — How are outgoing webhooks authenticated and retried?

Webhook deliveries include an HMAC-SHA256 signature, event identifier and timestamp. Consumers should verify the signature and reject stale timestamps. Failed deliveries retry with exponential backoff for up to 24 hours; consumers must deduplicate by event identifier.

## 16.5 — What formats are available for a full tenant export?

Tenant owners can request an asynchronous export containing case and contact JSON, CSV indexes and original attachment files in a ZIP archive. The download link expires after seven days. Exports omit internal security detections and data belonging to other tenants.
