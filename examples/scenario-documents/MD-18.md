## 18.1 — What is included in a standard implementation?

Standard implementation includes a kickoff, tenant configuration, administrator training and one CSV import rehearsal. The typical plan spans four to six weeks after the customer supplies clean data and identity-provider access. Custom connector development is outside the standard scope.

## 18.2 — Which historical data can be imported from a legacy system?

The supported migration template accepts cases, contacts and comments through CSV, with attachments supplied in a mapped ZIP archive. Import does not preserve the legacy system's audit signatures or executable workflow rules. Trial imports run in a separate migration tenant.

## 18.3 — What does the customer provide during onboarding?

The customer names a project owner, supplies the user roster and role mapping, configures the identity provider and signs off on the migration sample. MeridianDesk cannot complete SSO setup without an authorized customer identity administrator.

## 18.4 — Is a sandbox environment included?

Enterprise includes one sandbox tenant with synthetic starter data and separate API credentials. It is not automatically refreshed from production and must not receive unrestricted production exports. Starter plans do not include a persistent sandbox.

## 18.5 — How is migration acceptance verified?

Implementation compares source and imported record counts, samples relationships and attachments, and obtains customer acceptance before cutover. Failed rows are returned with row-level reasons for correction. A successful file upload alone does not constitute migration acceptance.
