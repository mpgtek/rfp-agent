## 8.1 — How are customer tenants isolated?

The service uses a shared application tier and shared regional database clusters. Every customer record carries a tenant identifier, and authorization checks constrain queries to that tenant. Enterprise plans do not include a dedicated database or dedicated compute cluster.

## 8.2 — Are production and nonproduction environments separated?

Production and staging run in separate cloud accounts with separate identities, networks and secrets. Production customer data is not copied into developer environments; test fixtures are generated or irreversibly anonymized before use.

## 8.3 — Is database infrastructure directly reachable from the internet?

No. Production databases use private network addresses and accept connections only from approved application and maintenance paths. Administrators use an audited access gateway; opening a public database endpoint is prohibited by deployment policy.

## 8.4 — What protections exist against denial-of-service attacks?

The public edge uses managed DDoS filtering, a web application firewall and request throttling. Platform staff monitor saturation and can temporarily restrict abusive traffic. These measures reduce exposure but do not promise uninterrupted service under every attack.

## 8.5 — Can the product run in a customer's own cloud account?

No. MeridianDesk is delivered as an operated multitenant SaaS. On-premises deployment, customer-managed Kubernetes and deployment into a customer's cloud subscription are not supported.
