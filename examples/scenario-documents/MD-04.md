## 4.1 — How does role-based access control work?

The built-in tenant roles are Owner, Administrator, Agent and Read-only Auditor. The application checks tenant membership and resource permissions on each server-side request. Only Owners can change billing contacts or delete the tenant.

## 4.2 — Can customers define custom permission roles?

Enterprise tenants may create up to 20 custom roles by combining published permissions. Field-level permissions and arbitrary scripting of authorization rules are not available. Starter tenants use built-in roles only.

## 4.3 — How is employee access to production approved?

Engineers request temporary production access through the access workflow with a ticket reference and manager approval. Privileged grants expire after four hours, require workforce MFA and are recorded in the administrative audit log.

## 4.4 — How frequently are privileged access rights reviewed?

Security reviews production administrator access every quarter and on role changes. Tenant administrators receive a downloadable user-and-role inventory, but customer access reviews are the tenant owner's responsibility.

## 4.5 — How are service accounts and API tokens restricted?

Each API token belongs to a tenant service account and has explicit read/write scopes. Tokens are displayed only at creation, may expire in 1 to 90 days, and can be revoked immediately. Shared employee credentials are prohibited.
